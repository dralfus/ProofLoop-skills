# Qwen Recon Lifecycle Replacement Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the ambiguous recon continuation model with a lifecycle in
which every new recon session has a new receipt, identity set and empty genesis
ledger, while terminal and active ledger attachment rules are fail-closed.

**Architecture:** Keep `qwen_recon_guard_decision(payload: object)` as the deep
pure policy module and external seam. The PowerShell launcher is the Adapter
that creates receipt identities and invokes the fixed read-only CLI contract.
Same-session ledger updates require the exact same receipt identity; a new
launch is never accepted with a non-empty old ledger. Protocol code remains a
separate module and is not modified.

**Tech Stack:** Python standard library, Python `unittest`, PowerShell 7,
JSON Schema, Markdown, append-only SHA-256 ledger projections.

**Spec:** `docs/superpowers/specs/2026-09-21-qwen-recon-lifecycle-replacement-design.md`

## Global Constraints

- Recon has no `continuation` field or continuation semantics; protocol-side
  `continuation` remains unchanged.
- Every new recon session creates a new `receipt`, `launch_id`, `session_id`,
  `ledger_id`, genesis anchor and non-reused `fresh_evidence_id`.
- A terminal recon ledger is permanently closed.
- A new `launch_id` cannot attach to an active non-terminal ledger.
- `fresh_evidence_id` is generated by the launcher and is not accepted from an
  observation payload.
- The pure policy receives a raw-free `used_fresh_evidence_ids` registry
  projection and fails closed when it is missing for a new genesis session.
- `stop_reason` and `writes` are required report fields with schema-equivalent
  type checks; `EVIDENCE_FOUND` requires `stop_reason=null` and `writes=[]`.
- `role_dispatch`, `subagent_dispatch` and `acceptance` remain false for every
  recon outcome.
- Protocol argv, protocol receipt, Ticket 16 security gates and acceptance
  authority are unchanged.
- Do not run live Qwen/recon/protocol, Implementer, role-agents or acceptance
  while executing this plan unless separately authorized.
- Preserve unrelated Ticket 16-19 changes, research files and dirty worktree
  content; do not create a commit in this execution.

## Review Focus

- A new launch with an active old ledger must fail before any observation is
  appended; test this in Task 1.
- A terminal old ledger must fail for both the old and a fresh receipt; test
  both cases in Task 1.
- A fresh genesis ledger without `fresh_evidence_id`, or with a reused token,
  must never return `QWEN_RECON_READY`; test identity validation in Task 1 and
  launcher uniqueness in Task 3.
- Any recon payload containing `continuation` must be rejected and no
  recon-specific code/schema/test may use it; pin the field rejection in Task 2
  and run the static scan in Task 6.
- Missing/null/wrong-type `stop_reason` or `writes` must be rejected before
  `QWEN_RECON_READY`; pin schema and launcher behavior in Task 4.

### Task 2: Implement the replacement pure recon lifecycle module

**Files:**

- Modify: `scripts/validate_plugin.py` in `_recon_receipt_reason`,
  `_recon_ledger_reason`, `_recon_observation_is_valid`,
  `_recon_observation_projection`, and `qwen_recon_guard_decision`.
- Test: `tests/test_qwen_runtime_lifecycle.py`

**Interfaces:**

- `qwen_recon_guard_decision(payload: object) -> dict[str, object]` remains the
  only public recon policy seam.
- `_recon_receipt_reason(...)` validates receipt identity fields including
  `session_id`, `ledger_id` and `fresh_evidence_id`.
- `_recon_observation_projection(receipt, observation)` binds receipt identity
  into the append-only event and does not accept continuation fields.
- `payload.used_fresh_evidence_ids` is a list of raw-free evidence identities
  projected by the receipt-registry Adapter.

- [ ] **Step 1: Reject the old recon field and validate identity binding.**

  Reject unknown recon observation fields, especially `continuation` and
  observation-level `fresh_evidence_id`. Require non-empty 32-character hex
  `launch_id`, `session_id`, `ledger_id` and `fresh_evidence_id` in the receipt.
  Require `observation.session_id == receipt.session_id` and
  `ledger_anchor.ledger_id == receipt.ledger_id` for both empty and non-empty
  ledgers.

- [ ] **Step 2: Enforce state transitions before append.**

  Keep hash-chain validation, then apply these checks in order:

  ```text
  ledger is terminal              -> RECON_TERMINAL_LEDGER_CLOSED
  ledger is active and launch differs
                                    -> RECON_ACTIVE_LEDGER_LAUNCH_MISMATCH
  ledger is active and session differs
                                    -> RECON_ACTIVE_LEDGER_SESSION_MISMATCH
  ledger identity differs from receipt
                                    -> RECON_RECEIPT_LEDGER_MISMATCH
  ledger is empty                  -> require genesis anchor and fresh receipt
  ```

  A same-session append must use the exact receipt identity, including the same
  `fresh_evidence_id`. Delete all recon branches named
  `CONTINUATION_FORBIDDEN`, `FRESH_SESSION_EVIDENCE_REQUIRED` and
  `FRESH_SESSION_EVIDENCE_REUSED`; replace the last one with the recon-specific
  terminal reason `RECON_FRESH_EVIDENCE_REUSED` at the receipt-registry seam.

- [ ] **Step 3: Bind fresh evidence to the first event.**

  Store `receipt.fresh_evidence_id` in the first recon ledger projection. Later
  same-session observations must match it. A new receipt must start with an
  empty ledger and a new registry token; it must never reuse an old ledger's
  evidence identity.

- [ ] **Step 4: Run the focused lifecycle suite.**

  Run:

  ```powershell
  python -m unittest tests.test_qwen_runtime_lifecycle
  ```

  Expected: all identity, active-ledger, terminal-ledger and no-continuation
  regressions pass.

## Disposition summary

The implementation must replace the recon-specific Ticket 20 lifecycle slice;
it must not layer another conditional onto the old `continuation` model.
Shared hash, worktree, capability, report and protocol adapters remain where
their interfaces do not encode recon session transitions. No commit is part of
this plan.
