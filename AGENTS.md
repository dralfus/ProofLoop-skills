# Инструкции для агентов

Этот репозиторий определяет повторяемый workflow разработки с AI-агентами.

Перед предложением изменений прочитайте:

- `README.md`;
- `docs/current-state.md`;
- `docs/target-workflow.md`;
- `docs/decisions.md`;
- `docs/codex-task-lifecycle.md`.

Исполняемый протокол версии `1.3` находится в
`plugins/agentic-development-workflow/skills/finish-ticket/references/task-lifecycle.md`.
При изменении ролей, health gates или acceptance authority обновляйте прежде
всего его, а человеческие документы и plugin — согласованно.

## Основная цель

Повышать надёжность перехода от реализации к подтверждённому завершению без
неограниченного расхода агентских раундов и контекста.

## Наблюдаемые failures

1. Ложное завершение: Implementer заявляет готовность при неполном выполнении.
2. Нездоровый repair-loop: review порождает повторяющиеся исправления,
   архитектурное проектирование внутри implementation, вложенных agents и
   чрезмерный расход токенов.

## Принципы

1. Отделять реализацию от приёмки.
2. Предпочитать независимое evidence самооценке агента.
3. Только Controller создаёт role-agents.
4. Останавливать повторяющуюся корневую причину раньше абсолютного лимита.
5. Отделять design gaps от implementation fixes.
6. Выбирать модель по риску задачи, а не только по цене одного запуска.
7. Запускать дорогую verification после статического review.
8. Добавлять процесс только в ответ на наблюдаемый failure mode.
9. Проверять изменения workflow на реальных development cases.
10. До дорогих role-agent запусков объявлять и соблюдать budget модели,
    verification и context compaction.

## Дисциплина изменений

При изменении workflow:

1. назвать конкретный failure mode;
2. объяснить, почему текущий workflow его не обработал;
3. предложить минимальное изменение;
4. определить измеримый критерий улучшения;
5. записать принятое решение в `docs/decisions.md`;
6. обновить канонический протокол, plugin и человеческую инструкцию
   согласованно.
